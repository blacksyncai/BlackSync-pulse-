# Workspace-owned CRM numbers

The CRM no longer exposes the carrier account's number inventory or the legacy `PLIVO_CALLER_ID`. No legacy number is grandfathered into a workspace. Browser voice uses a dedicated `blacksync_crm_voice_v2` application/endpoint; AI campaign applications and numbers are not repointed.

**Setup → CRM phone numbers** searches US local voice inventory and opens a server-priced Stripe subscription Checkout ($3.50 USD/month, one selected number). Billing permission is required to purchase or manage subscriptions. Applicable Stripe promotion codes are accepted. Phone rental is separate from calling usage. The CRM purchase has its own order records and Stripe purchase type; it does not grant AI campaign phone-number entitlements.

A real, live-mode paid/no-payment-required Checkout and an active subscription are required before carrier provisioning. The server stores the Checkout ID and validates its reference, subscription, quantity, currency, recurring interval and price. It never assigns a workspace from an arbitrary webhook metadata field. Existing carrier numbers are never adopted; an exact order-marked CRM number can be recovered after an uncertain carrier response. A failed provisioning attempt stays pending attention rather than silently substituting another number.

The first checkout registers a dedicated signed Stripe webhook; its signing secret is AES-GCM encrypted using the app secret. Subscription changes, renewal payments, failed payments, cancellations, refunds, disputes and early fraud warnings trigger reconciliation. Risk events resolve the Stripe Charge/Customer to the server-owned orders and suspend their entitlements. Current Stripe subscription state is authoritative, so stale events cannot reactivate a canceled number. The existing five-minute worker also reconciles orders. Canceled or past-due subscriptions disable calling; carrier numbers remain reserved rather than being automatically released or reassigned. The billing portal manages each number's subscription separately.

Each call requires a fresh, opaque, 90-second authorization bound to workspace, member, purchased number, destination and recording preference. The carrier callback rechecks membership and number entitlement and ties the authorization to its carrier call UUID. Legacy headers and unsigned calls fail closed. A stale browser caller-ID preference cannot grant another workspace's number. Expired authorizations are pruned after a day. Secrets and call authorization tokens are not logged.

The public `/webhooks/crm-phone-numbers/status` exposes only configuration booleans and rental price. Purchase credentials are required in `BILLING_STRIPE_API_KEY` and `PLIVO_AUTH_ID`/`PLIVO_AUTH_TOKEN`. Deployment checks existing Railway/GitHub billing credentials without logging them; existing live Stripe keys under common names can be reused. An absent key disables checkout rather than falling back to shared numbers. Live carrier purchases from Stripe test-mode payments are blocked.

Validation uses mocked carrier/Stripe infrastructure for tenant isolation, call replay/destination tampering, removed members, suspended entitlements, server-side price/promotion handling, payment gating, AI number non-adoption, renewal failure and uncertain-purchase recovery. Existing XML/token tests also remain. Real payment and carrier provisioning require completing Checkout; no real test charge or number purchase was performed during development. Incoming calls and SMS are not enabled by this outbound browser-calling change.
